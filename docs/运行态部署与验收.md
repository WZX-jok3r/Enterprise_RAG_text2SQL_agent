## 逐步验收

1. Compose 配置、依赖清单、镜像编译和模块导入通过后运行迁移；迁移成功后更新服务。
2. API、worker 镜像 ID 和源码一致；两个容器分别执行受限 SQL 测试：COUNT 允许，salary 和整行 JSON 查询拒绝。版本登记与采集模块运行通过；采集用量是合成响应，不代表真实供应商 usage。
3. API 健康探针、前端页面及反向代理通过。缺失 Key 返回 401，无效 Key 返回 403，合法身份可访问文档列表。
4. 通过真实 HTTP 上传空白 TXT，实际 Redis/ARQ worker 解析后将任务和文档标为 failed，不产生 Embedding 调用，不发布当前版本。失败版本激活返回 409，跨租户查询任务/版本、删除及激活返回 404。本次 worker 日志中的空文件 ValueError 是预期的失败保护证据。
5. 使用本次随机标识创建 READY 测试记录，通过真实 HTTP 激活新版本、回滚旧版本并读取历史。READY 状态是合成夹具，不代表真实成功的模型入库。
6. 在两容器内的独立进程调用部署的 VectorStore.search，使用固定向量、独立 Qdrant 集合和 PG 版本登记，验证历史版本隐藏、回滚后的旧版本可见、跨租户检索无结果。测试不替换运行 API/worker 的模型依赖，不修改生产集合。
7. 每轮清理只删除本轮 UUID 的文档、文件、任务、ARQ 结果和独立集合；验收报告清理错误为零。

## 重跑

从项目根执行：

```powershell
.venv\Scripts\python.exe scripts/runtime_acceptance.py
```

脚本需要本地 Docker、PostgreSQL、Redis、Qdrant 以及正在运行的 API/worker/前端；至少两个已配置租户用于越权检查。它从现有配置取密钥，不打印密钥。任意断言失败即停止后续步骤，报告 `passed=false`；测试数据在 finally 中清理。报告保存为 `output/runtime_acceptance.json`，覆盖上次结果，正式发布归档时应复制为带版本/日期的文件。

## 尚未覆盖

本次解决了代码与运行版本不同步，并通过无需外部模型的运行态验收。真实非空文档 Embedding 入库成功链路、真实答案质量、供应商费用与容量、Qdrant 物理快照故障以及 Redis/队列容灾仍未验收。当前环境仍为 development，默认角色保留原配置；这不是生产安全配置或生产部署验收。生产必须按配置校验要求建立 employee 默认角色与显式授权。
