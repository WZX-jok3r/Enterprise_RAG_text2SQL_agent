# 10 · 运行、部署、测试与评测

## 1. 环境与依赖

- Python 3.12+（后端）；Node.js/npm（前端）；Docker Compose（容器化）。
- 后端环境：在 `backend/` 执行 `uv sync --locked`（无 uv 时改 `pip install -e . && pip install pytest pytest-asyncio`），虚拟环境固定落在 `backend/.venv`。
- 前端：`cd frontend && npm ci`。

## 2. 配置准备

从项目根目录 `Copy-Item .env.example .env`，关键配置：

| 配置 | 用途 |
| --- | --- |
| `SILICONFLOW_API_KEY` | 模型/Embedding/Rerank 凭据 |
| `LLM_MODEL` / `EMBEDDING_MODEL` / `RERANK_MODEL` | 模型选择；换 Embedding 需同步 `VECTOR_DIM` 并重建索引 |
| `QDRANT_COLLECTION_NAME` / `VECTOR_DIM` | 向量集合与维度 |
| `RAG_TENANT_KEYS` | `tenantA=keyA;tenantB=keyB`，Key→租户 |
| `DEFAULT_ROLE` / `RAG_TENANT_ROLES` | 角色（analyst/employee） |
| `SQL_REDACT_COLUMNS` | 敏感列（默认 `employees.salary,employees.email`） |
| `ANALYTICS_RO_PASSWORD` / `ANALYTICS_EMPLOYEE_PASSWORD` | 两类 SQL 登录口令 |
| `SQL_MAX_ROWS` / `SQL_TIMEOUT_MS` | SQL 行数/超时 |
| `PERFORMANCE_LOG_FILE` | 可选性能采集，默认关 |

配置查找顺序：项目根 `.env` → `backend/.env`（后者覆盖）；容器内全来自环境变量。本地后端读根 `.env`。

## 3. 容器启动

```powershell
# 项目根目录
docker compose -f docker_setting/docker-compose.yml up -d --build
docker compose -f docker_setting/docker-compose.yml ps
```

Compose 含 PostgreSQL、Redis、Qdrant、API、worker、前端与一次性迁移服务；API/worker 复用后端镜像，等迁移成功后启动。

访问：

| 地址 | 用途 |
| --- | --- |
| `http://localhost:8080` | 前端问答与文档管理 |
| `http://localhost:8000/docs` | OpenAPI 文档 |
| `http://localhost:8000/api/v1/health` | 存活检查 |
| `http://localhost:6333/dashboard` | Qdrant 管理页 |

## 4. 本地开发

```powershell
# 安装依赖 + 初始化业务库（依赖装在 backend/.venv）
cd backend && uv sync --locked              # 无 uv 时：pip install -e . && pip install pytest pytest-asyncio
python -m app.ops.setup_db            # 建库 + 只读/受限角色 + 权限自检
python -m app.ops.seed --all --verify # 装载默认演示表并验证真值

# 迁移（版本管理功能必须执行）
alembic upgrade head

# 终端 1：API
uvicorn app.main:app --reload
# 终端 2：worker
arq app.worker.settings.WorkerSettings

# 前端
cd frontend && npm ci && npm run dev
```

## 5. 测试

从 `backend/`（激活虚拟环境）：

```powershell
python -m pytest -q
```

从根目录（脚本固定调用 `backend/.venv` 的解释器）：

```powershell
.\scripts\check.ps1          # 编译检查 + 后端测试（字节码与 pytest 缓存重定向到 %TEMP%，仓库不留 __pycache__）
.\scripts\check.ps1 -Full    # 另加检索评测与逐题基线比对
```

前端：`cd frontend && npm run build`（TypeScript 校验 + 生产构建）。

**测试约束**：service 依赖测试可无凭据/数据库跳过并报告；`asyncio_mode=auto`；未配置覆盖率阈值。真实模型测试在凭据/服务可用时才执行，离线验证应先用不含真实凭据的环境。

当前基线（2026-11-11 本机复跑）：backend 测试 **745 passed、147 skipped**（合计 892，0 failed）；SQL 攻击测试 54 拦截/19 放行；检索召回基线 Recall@5 99.01%、MRR 0.9703。147 项跳过均因未起 PostgreSQL/Qdrant 或未配模型凭据，跳过不计入通过。

## 6. 评测工具 — `backend/eval/`

| 命令 | 用途 |
| --- | --- |
| `python -m eval --retrieval-only` | 检索评测（不调 LLM） |
| `python -m eval.compare --baseline baseline_v1` | 逐题基线比对 |
| `python -m eval` | 完整评测（107 题通过率 + 关键词命中率） |
| `python -m eval.quality --live ...` | 答案质量（生成 + 评审各一轮模型） |
| `python -m eval.text2sql_runner --dry-gold` | 验证 Gold SQL 可执行（不调 LLM） |
| `python -m eval.text2sql_runner` | 实际 Text2SQL 评测（调模型） |
| `python -m eval.performance --mode fixture ...` | 合成本地 HTTP 性能基准 |

评测模块：`runner.py`（检索）、`compare.py`（基线比对）、`quality*.py`（答案质量生成/评审/指标/模型）、`performance*.py`（性能与合成基准）、`text2sql_runner.py`（Text2SQL）。

## 7. 演示顺序建议

1. **文档问答**：上传质保政策 → 问质保期限 → 检查来源与版本。
2. **精确统计**：问 Sales 与 Engineering 人数及差值 → 检查 SQL 与结果。
3. **租户隔离**：切换租户 Key → 验证读不到前一租户私有文档。
4. **版本切换**：同名上传修改版 → 发布后新会话验证 → 回滚旧版本。
5. **权限验证**：配置 employee 角色 → 确认敏感字段查询被拒绝/脱敏。

## 8. 注意事项

- `.env`、私钥、私有上传文件不要提交。
- 生产部署需另配口令、网络暴露、TLS、镜像版本、备份与监控。
- OCR 能力（PDF 扫描件等）需额外 Python/系统依赖。
- liveness（`/health`）不代表下游就绪；`/metrics` 无业务鉴权，应限制到监控网络。
- 版本切换后建议新会话验证，避免旧对话记录影响观察。
