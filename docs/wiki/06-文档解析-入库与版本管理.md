# 06 · 文档解析、入库与版本管理

## 1. 概览

文档从上传到可检索，分两条路径：

1. **版本化上传**（API，主流）：`POST /documents` 落盘 `.versions/` 不可变文件 → 登记 → ARQ 入队 → worker `ingest_version` → 发布。
2. **CLI 全量入库**（历史兼容/演示）：`python -m app.ingestion.indexer` 扫描 `knowledge_base/` 增量入库。

## 2. 多格式解析 — [loader.py](file:///d:/PythonProjects/personal_rag/backend/app/ingestion/loader.py)

统一入口 `load_file(file_path)` 按后缀派发 `FORMAT_LOADER_MAP`：

| 格式 | 解析器 | 要点 |
| --- | --- | --- |
| `.pdf` | `load_pdf` | pdfplumber→pymupdf.get_tables→dict 三级表格提取、双栏检测重排、旋转校正、OCR 兜底（pytesseract）、双页码系统、marker 深度识别 |
| `.docx` | `load_docx` | 段落 + Markdown 表格 + 图片 OCR（双轨采集 inline/header-footer） |
| `.xlsx` | `load_xlsx` | openpyxl（保留合并单元格）→ pandas 降级；大表（≥1000 行）额外生成全表聚合摘要块 |
| `.txt` | `load_txt` | 自动编码检测（utf-8/gbk/latin-1） |
| `.md` | `load_md` | 保留原始 markdown |

统一结构 `Document {text, metadata}`。`compute_file_hash()` 做 MD5 增量判断。

## 3. 分块 — `app/ingestion/chunking/`

`chunk_document(doc_dicts)` 产出 `Chunk` 列表；`parser=="marker"` 的 PDF 结果走 Markdown 表格感知切分，其余按文本/表格策略切分。配置项 `default_chunk_size/default_chunk_overlap`。

## 4. 索引 — [indexer.py](file:///d:/PythonProjects/personal_rag/backend/app/ingestion/indexer.py)

`process_file(file_path, vector_store, tenant_ids, version_context)` 单文件处理：

1. 清旧向量（version 按 `document_version_id` 精确清理，legacy 按 `source`）。
2. 解析 → 分块。
3. 可选项注入文档名前缀（`INDEX_FILENAME_PREFIX`，让 BM25/rerank 能命中“点名文件”）。
4. 写多租户 ACL（`tenant_id` 列表整体写进 chunk metadata）。
5. `upsert_chunks` 批量写入（dense + bm25 双通道）。

`run_ingest()` / `ProcessedCache` 提供 CLI `--force/--reset/--tenant/--files` 增量入库。

## 5. 向量写入 — [qdrant.py](file:///d:/PythonProjects/personal_rag/backend/app/vector/qdrant.py) `upsert_chunks`

每个 chunk 生成 point：`id` 由 `document_version_id + version_chunk_index + text`（或 `source + text[:200]`）MD5 生成保证幂等覆盖；`vector` 双通道 `{dense, bm25}`；`payload` 展开全部 metadata + `text`。

## 6. 异步入库 worker

### 6.1 任务配置 — [settings.py](file:///d:/PythonProjects/personal_rag/backend/app/worker/settings.py)

`WorkerSettings`：`functions=[ingest_document]`、`max_jobs=1`（单并发保证同文件不并行重灌）、`job_timeout=600`；`on_startup` 注入 `ctx["db"]` 与 `ctx["vector_store"]`。

### 6.2 任务函数 — [ingest.py](file:///d:/PythonProjects/personal_rag/backend/app/worker/tasks/ingest.py)

`ingest_document(ctx, file_path, task_id, tenant_ids, version_id)`：

- `version_id` 非空 → 转 `ingest_version`（版本化）。
- 否则：置 running → `process_file`（线程池）→ 登记 Document 终态 + 任务 done。
- 表格文件：`should_sync_to_analytics` 时 `sync_analytics_tables` 同步 SQL 侧；**失败不阻断 RAG 入库**（不 re-raise）。

### 6.3 版本化任务 — [versioned_ingest.py](file:///d:/PythonProjects/personal_rag/backend/app/worker/tasks/versioned_ingest.py)

`ingest_version(ctx, file_path, task_id, version_id)`：

- 校验任务/版本绑定与所属租户；状态已就绪直接返回（重复投递绝不撤销用户已执行的回滚）。
- 用 `DocumentVersionRepository.lock(document_key)`（advisory lock）串行化同文档族操作。
- 校验不可变文件（basename 与 file_hash 前后一致）。
- `process_file` 写版本向量 → 置 `ready` → `publish(automatic=True)`。
- 失败置 `failed` 并 re-raise 触发 ARQ 重试。

## 7. 版本管理 — [document_version_repo.py](file:///d:/PythonProjects/personal_rag/backend/app/repositories/document_version_repo.py)

| 方法 | 说明 |
| --- | --- |
| `document_key(tenant_id, filename)` | sha256 生成租户内文档族标识 |
| `reserve()` | 分配新版本号（`version+1`）；同名同 hash 复用 |
| `lock(key)` | `pg_advisory_xact_lock` 串行化分配/发布/删除 |
| `publish(doc, automatic)` | 先清旧 `is_current`，再置新版本为当前；automatic 时若已有更新版本则不覆盖 |
| `history()` / `owned()` | 版本历史 / 精确归属校验（匿名调用者也不把 None 当通配符） |

## 8. 删除与回滚

- `IngestionService.delete_document`：清向量 → 删物理副本 → 删登记行，任一外部失败保留登记行可重试。
- `INGEST_JOB` 稳定 job id（`ingest:<task_id>`）幂等；失败由 ARQ 按 `max_tries` 重试。
- 版本化删除：先 `is_current=False, status='deleted'`（事务内隐藏），外部清理可重试，不因清理失败暴露数据。

## 9. 支持后缀与边界

`settings.supported_extensions = {".pdf", ".docx", ".xlsx", ".md", ".txt"}`。上传时 `_safe_target_path()` 校验后缀、防目录穿越/重名覆盖，落盘到 `knowledge_base/.versions/`。

**当前边界**：版本化表格只进 RAG，不同步发布/回滚 SQL 数据表（见 [01 概览](01-项目概览与架构.md)）。OCR（PDF 扫描件、DOCX 图片）需要额外 pytesseract 依赖。
