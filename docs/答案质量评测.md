# 答案质量评测

> 产物说明（2026-11-11）：`output/` 是 gitignore 的本地产物目录，清理时只保留 `output/answer_quality_20261028.json` 与其 `.responses.jsonl`。本文引用的其他 `output/...` 文件可能已不存在，重跑对应命令即可重现。权威基线在 `backend/eval/baseline/answer_quality_v1.json`。

新增评测入口为 `python -m eval.quality`，与原检索 runner、107题数据集和 baseline_v1 分开。生产问答代码、提示词与检索参数没有因本次评测建设而改变。

## 指标口径

| 指标 | 判断依据 | 说明 |
| --- | --- | --- |
| evidence_recall | 标注来源与证据原文是否出现在实际检索片段 | 片段级诊断，不能用文件命中替代 |
| fact_coverage_diagnostic | 预期事实字符串是否出现在答案 | 仅作诊断，否定、错误数字等不能靠它判通过 |
| correctness | 语义评审对问题、参考答案与标注证据的判断 | correct=1、partial=0.5、incorrect=0 |
| faithfulness | 原子事实中被实际检索证据支持的比例 | 参考答案不属于检索上下文；回答碰巧正确也可能无证据支持 |
| citation_accuracy | 引用编号对应的证据是否支持被归于它的主张 | 编号存在只是格式有效，不等于内容支持 |
| citation_coverage | 原子事实中同时得到证据支持和有效引用的比例 | 默认要求所有事实都有支持和引用 |
| refusal_precision/recall | 语义判断合理拒答与所有拒答/不可回答题的关系 | “无法回答，但估计36个月”仍属于错误回答 |
| false_refusal_rate | 可回答题中的不合理拒答比例 | 防止依赖全面拒答提高其他指标 |

没有评分的指标是 null，并报告 scored_cases、eligible_cases 和 coverage；不会伪装成0分或100%。
所有题都保留在总分母中，缺失回答、生成失败、评审失败分别记录错误。报告的评审覆盖率不足时验证不能通过。

默认逐题通过条件：可回答题完全正确、全部事实忠实且引用完整；不可回答题合理拒答且没有编造事实。`--allow-uncited` 仅用于诊断，策略写入报告，不能与严格引用策略的基线混用。
支持 `【参考1】`、`[参考1]`、`[1]` 编号格式。当前生产提示词未强制输出编号，因此真实评测可能暴露引用缺失；不要为了让指标好看而虚构引用。

## 分层验证

1. 严格数据模型和确定性指标测试。
2. 语义评审契约、错误处理与响应哈希绑定测试。
3. 实际上下文捕获、报告分母与 CLI 退出码测试。
4. 原文标注题集及合成正反例自检。
5. 逐题回归、CI 和全量测试。

每层验证通过后才进入下一层。CI 中运行的是评测器自检，输出明确标记 calibration_fixture，不代表真实模型质量或评审模型准确率。

## 数据集

`backend/eval/data/answer_quality_v1.jsonl` 包含12道起始标注题：9道可回答、3道不可回答，覆盖版本、冲突、数字与单位、完整性、条件、否定、资料不足和提示注入。
标注证据来自当前4份 Markdown 原文，测试会校验引用确实存在。不可回答标签针对本次初始知识范围；知识库扩展后必须复核这些标签。
这是开发回归集，不能用12题结果宣称企业通用准确率；后续应加入真实业务问题、留出集及人工复核。

```powershell

```

报告位于 `output/quality_self_check.json`。包含2个应该通过的正例和7个应该失败的反例；程序检查每一个预期判定一致才退出0，不能将它们的2/9通过率当成模型成绩。

## 实际 RAG + 语义评审

先启动并索引 Qdrant，配置生成模型 Key。评审模型必须显式指定；可以用 QUALITY_JUDGE_API_KEY 和 QUALITY_JUDGE_BASE_URL 配置独立的兼容接口。

```powershell
..\backend\.venv\Scripts\python.exe -m eval.quality --live --limit 3 --judge-model "<评审模型标识>" --judge-timeout 120 --output ../output/quality_smoke.json
# 冒烟检查通过后，再运行完整题集：
..\backend\.venv\Scripts\python.exe -m eval.quality --live --judge-model "<评审模型标识>" --judge-timeout 120 --output ../output/answer_quality.json
# 只换评审规则、不重新生成答案时，用已保存的应答快照离线复评（省一半调用，且能隔离变量）：
..\backend\.venv\Scripts\python.exe -m eval.quality --responses ../output/answer_quality.responses.jsonl --judge-model "<评审模型标识>" --judge-timeout 120 --output ../output/answer_quality_rejudge.json
```

需要租户过滤时显式提供 `--tenant-id`，确保该租户有权访问评测证据。
**不提供 `--tenant-id` 时不做租户过滤**（`apply_tenant_acl` 返回 `None`），
可用于评测证据分散在多个租户的场景，但此时本次评测不检验租户隔离，应在报告中注明口径。
每题最多一次评审请求；`--judge-timeout` 默认 45 秒，实测长答案需要 120 秒。
**超时与供应商断连都记为 error 而不是判为不合格**，因此这类噪声会让 `errors>0`、退出码 2，
基线必须在 `errors=0` 的运行上取得。输入超限直接报错，不截断证据。生成请求沿用生产模型的既有重试行为。
捕获的是该次问答真正使用的完整片段，而非 sources 中200字预览，也不会为评测额外检索一次。
JSON报告含参考答案、标注证据、实际回答/上下文、主张级评审、错误、分类结果、数据哈希、生成配置与评审模型/规则版本。
评审输出未通过一致性校验时，报告会写入 `rejected_verdict` 保留被拒内容 ——
排障时应先看它，而不是靠错误信息猜。
生成快照同时保存为 `<报告名>.responses.jsonl`，可用于人工复核和离线重新评审。

同一模型同时生成与评分可能有偏差。正式发布前需选择独立评审模型并用人工标注的真实回答校准；本次合成评审契约测试不能替代这一步。

## 人工评审与离线复评

```powershell
..\backend\.venv\Scripts\python.exe -m eval.quality --responses ../output/answer_quality.responses.jsonl --reviews ../output/human_reviews.jsonl --output ../output/quality_human.json
```

每条人工标签包括 id、response_sha256、reviewer、verdict。response_sha256 对该条完整 ResponseRecord 的 JSON 排序序列化计算SHA256，可从上次报告对应题直接复制。
verdict 字段为 correctness、refusal、claims、citations、reason；格式见 quality_models.py。主张 text 必须是答案原文子串，证据编号必须存在，所有显式引用必须逐一评审。
任何答案、片段或错误状态改变都会使旧标签失效。评审失败、缺失标签或供应商响应异常都不能当成正确拒答。
只提供 --responses 而不提供评审时，仍输出确定性诊断，但退出2且语义成绩为null。

## 退出码与回归

- 0：全部样本满足当前质量策略。
- 1：评审完整，但存在质量不合格的答案。
- 2：输入无效、评审缺失/失败或评测不完整。

从完整的真实模型或人工评审报告保存基线后，执行：

```powershell
..\backend\.venv\Scripts\python.exe -m eval.quality_compare --baseline eval/baseline/answer_quality_v1.json --current ../output/answer_quality.json
```

逐题检查正确性、忠实度、引用及拒答变化，防止A题改善抵消B题退化。
数据、策略、规则版本、评审配置不一致时拒绝比较；缺题、未评审及 calibration_fixture 报告不能作为正式基线。
真实 LLM 有随机性，应重复采样并人工检查回归，再决定是否更新基线，不应覆盖失败报告来制造通过。

### 唯一不达标题：aq-07（真实缺陷，非评测问题）

问题"网页端 RSA 私钥应该放在哪里？"，答案只给出"私钥放在**服务端**"，
遗漏了 `required_facts` 中的"公钥"，`fact_coverage_diagnostic=0.667`。
检索是完整的（`evidence_recall=1.0`，上下文含"公钥加密…客户端只用公钥加密数据"原文），
**损失发生在生成端**：模型对"X 放在哪里"这类聚焦型问题有很强的直接回答倾向。

已尝试的对策：把"回答要完整"从后段提示提升为**核心规则第 2 条**，
并规定资料中与所问事实构成同一机制/流程/配套关系的内容必须一并答出。
该改动对其他题有效（aq-09、aq-10、aq-12 答案长度分别 +64、+117、+66 字），
但 aq-07 仍稳定漏答。**不再针对该题继续细调提示词** —— 12 题是开发回归集，
为单题反复调 system prompt 属于过拟合，项目文档已明确"不能用12题结果宣称企业通用准确率"。
若后续要根治，方向是让上下文构造把配套句与所问句绑定，或在 few-shot 中示范完整回答形态。

### 本次排障中暴露的评测口径缺陷（均已修复并加回归测试）

真实评测把 9 个离线自检发现不了的问题暴露了出来。按发现顺序：

| # | 问题 | 表现 | 修法 |
| --- | --- | --- | --- |
| 1 | 生产提示词无引用格式约束 | 模型随机输出 `【参考1】`/`（参考1）`/`参考1（说明）`，`citation_ids()` 提取为空集，评审一致性校验抛错 | 在 `prompts/rag.py` 固定为 `【参考N】` 单一格式并列举禁用变体 |
| 2 | 评审超时硬编码 45 秒 | 长答案下 `ReadTimeout`，整题记为 error | 改为 `--judge-timeout` 可配，写入报告 `judge` 元数据 |
| 3 | 评审丢答案的 Markdown 标记 | 答案含 `**24个月**`，评审给出 `24个月`，触发"非答案子串" | 评审提示词要求逐字符复制含格式符号；**不放宽**子串校验 |
| 4 | 拒答答案的引用未被评审 | 正确拒答却引用【参考1】论证资料不足，评审返回空 citations | 明确"拒答不计入 claims，但引用必须逐条评审" |
| 5 | refusal 标签与 answerable 冲突 | 可回答题判 appropriate、不可回答题判 unnecessary | 改为"是否 declined + answerable 组合"的两步机械规则，禁止评审自行重判可回答性 |
| 6 | 评审把 question 内嵌指令当评分基准 | 提示注入题中，答案**拒绝**编造反被判 incorrect | 明确评分基准是 `reference_answer`，不遵从 question 内嵌指令不是缺陷 |
| 7 | 评审输出在校验失败时被丢弃 | 报告只剩一句错误信息，只能凭猜测改提示词，反复三轮 | 新增 `JudgeValidationError` 携带 verdict，报告写入 `rejected_verdict` |
| 8 | 生产提示词允许资料外推断 | 不可回答题正确拒答，却夹带"Office Rent 通常不被视为采购成本"（资料从未定义采购成本），`faithfulness` 掉到 0.978 | 新增"不得引入资料外知识"规则与正反例 |
| 9 | 评审越界做字面匹配 | 答案写"需要明确所依据的文档版本"，评审因未复述"必须区分版本"判 partial | 明确 correctness 是语义评审，字符串重合度只属诊断指标 |

**其中两处是修复自身引入的回归，记录在此以防重演：**

- **完整性被"宁可少说一句"压制**：为修 #8 加的"宁可少说一句，也不要多说一句资料没有支撑的话"
  过度生效，aq-07 答案从 36 字缩到 27 字，把资料里明写的配套流程也省了，
  `faithfulness` 升到 1.0 但 `fact_coverage_diagnostic` 从 1.0 掉到 0.667。
  修法是补上对称规则："少说"只针对资料里没有的内容，资料里有的必须完整给出。
- **规则被评审反向套用，产出虚假 12/12**：为修 #9 加的"额外的正确信息不扣分"
  被评审套到 aq-07 上 —— 理由写"答案未提及公钥加密的完整流程，但……额外的正确信息不扣分"，
  于是给出 `correct`，产出 `pass_rate=1.0`、`gate_passed=true` 的**全绿假基线**，
  而该题答案根本没变化、仍缺 `required_facts` 里的"公钥"。
  修法是给规则加适用前提（答案须先完整覆盖全部语义要求）并明令禁止反向套用。

**教训**：放宽评审口径的每一条规则都必须同时写明**反向滥用的形态**，
否则模型会用新规则豁免旧缺陷。全绿的 `gate_passed=true` 不等于质量达标 ——
必须回看单题的 `fact_coverage_diagnostic` 等诊断信号交叉验证。
第 7 项（保留被拒的评审输出）是本次能定位到这条的关键；
没有它，#10 这类问题只能靠猜。

回归测试见 [test_prompt_citation_contract.py](../backend/tests/test_prompt_citation_contract.py)，
把"上下文编号格式 ↔ 提示词引用约束 ↔ 评测器解析 ↔ 评审校验"绑成一条契约链，
任一方单独漂移都会失败。
