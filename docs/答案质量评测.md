# 答案质量评测

新增评测入口为 `python -m eval.quality`，与原检索 runner、107题数据集和 baseline_v1 分开。生产问答代码、提示词与检索参数没有因本次评测建设而改变。

## 指标口径

| 指标 | 判断依据 | 说明 |
| --- | --- | --- |
| evidence_recall | 标注来源与证据原文是否出现在实际检索片段 | 片段级诊断，不能用文件命中替代 |
| fact_coverage_diagnostic | 预期事实字符串是否出现在答案 | 仅作诊断，否定、错误数字等不能靠它判通过 |
| correctness | 语义评审对问题、参考答案与标注证据的判断 | correct=1、partial=0.5、incorrect=0 |
| faithfulness | 原子事实中被实际检索证据支持的比例 | 参考答案不属于检索上下文；回答碰巧正确也可能无证据支持 |
| citation_accuracy | 引用编号对应的证据是否支持被归于它的主张 | 编号存在只是格式有效，不等于内容支持 |
| citation_coverage | 原子事实中同时得到证据支持和有效引用的比例 | 默认要求所有事实都有支持和引用 |
| refusal_precision/recall | 语义判断合理拒答与所有拒答/不可回答题的关系 | “无法回答，但估计36个月”仍属于错误回答 |
| false_refusal_rate | 可回答题中的不合理拒答比例 | 防止依赖全面拒答提高其他指标 |

没有评分的指标是 null，并报告 scored_cases、eligible_cases 和 coverage；不会伪装成0分或100%。
所有题都保留在总分母中，缺失回答、生成失败、评审失败分别记录错误。报告的评审覆盖率不足时验证不能通过。

默认逐题通过条件：可回答题完全正确、全部事实忠实且引用完整；不可回答题合理拒答且没有编造事实。`--allow-uncited` 仅用于诊断，策略写入报告，不能与严格引用策略的基线混用。
支持 `【参考1】`、`[参考1]`、`[1]` 编号格式。当前生产提示词未强制输出编号，因此真实评测可能暴露引用缺失；不要为了让指标好看而虚构引用。

## 分层验证

1. 严格数据模型和确定性指标测试。
2. 语义评审契约、错误处理与响应哈希绑定测试。
3. 实际上下文捕获、报告分母与 CLI 退出码测试。
4. 原文标注题集及合成正反例自检。
5. 逐题回归、CI 和全量测试。

每层验证通过后才进入下一层。CI 中运行的是评测器自检，输出明确标记 calibration_fixture，不代表真实模型质量或评审模型准确率。

## 数据集

`backend/eval/data/answer_quality_v1.jsonl` 包含12道起始标注题：9道可回答、3道不可回答，覆盖版本、冲突、数字与单位、完整性、条件、否定、资料不足和提示注入。
标注证据来自当前4份 Markdown 原文，测试会校验引用确实存在。不可回答标签针对本次初始知识范围；知识库扩展后必须复核这些标签。
这是开发回归集，不能用12题结果宣称企业通用准确率；后续应加入真实业务问题、留出集及人工复核。

## 无外部服务自检

在 backend 目录运行：

```powershell
..\.venv\Scripts\python.exe -m eval.quality_calibration
```

报告位于 `output/quality_self_check.json`。包含2个应该通过的正例和7个应该失败的反例；程序检查每一个预期判定一致才退出0，不能将它们的2/9通过率当成模型成绩。

## 实际 RAG + 语义评审

先启动并索引 Qdrant，配置生成模型 Key。评审模型必须显式指定；可以用 QUALITY_JUDGE_API_KEY 和 QUALITY_JUDGE_BASE_URL 配置独立的兼容接口。

```powershell
..\.venv\Scripts\python.exe -m eval.quality --live --limit 3 --judge-model "<评审模型标识>" --output ../output/quality_smoke.json
# 冒烟检查通过后，再运行完整题集：
..\.venv\Scripts\python.exe -m eval.quality --live --judge-model "<评审模型标识>" --output ../output/answer_quality.json
```

需要租户过滤时显式提供 `--tenant-id`，确保该租户有权访问评测证据。
每题最多一次评审请求，超时45秒；输入超限直接报错，不截断证据。生成请求沿用生产模型的既有重试行为。
捕获的是该次问答真正使用的完整片段，而非 sources 中200字预览，也不会为评测额外检索一次。
JSON报告含参考答案、标注证据、实际回答/上下文、主张级评审、错误、分类结果、数据哈希、生成配置与评审模型/规则版本。
生成快照同时保存为 `<报告名>.responses.jsonl`，可用于人工复核和离线重新评审。

同一模型同时生成与评分可能有偏差。正式发布前需选择独立评审模型并用人工标注的真实回答校准；本次合成评审契约测试不能替代这一步。

## 人工评审与离线复评

```powershell
..\.venv\Scripts\python.exe -m eval.quality --responses ../output/answer_quality.responses.jsonl --reviews ../output/human_reviews.jsonl --output ../output/quality_human.json
```

每条人工标签包括 id、response_sha256、reviewer、verdict。response_sha256 对该条完整 ResponseRecord 的 JSON 排序序列化计算SHA256，可从上次报告对应题直接复制。
verdict 字段为 correctness、refusal、claims、citations、reason；格式见 quality_models.py。主张 text 必须是答案原文子串，证据编号必须存在，所有显式引用必须逐一评审。
任何答案、片段或错误状态改变都会使旧标签失效。评审失败、缺失标签或供应商响应异常都不能当成正确拒答。
只提供 --responses 而不提供评审时，仍输出确定性诊断，但退出2且语义成绩为null。

## 退出码与回归

- 0：全部样本满足当前质量策略。
- 1：评审完整，但存在质量不合格的答案。
- 2：输入无效、评审缺失/失败或评测不完整。

从完整的真实模型或人工评审报告保存基线后，执行：

```powershell
..\.venv\Scripts\python.exe -m eval.quality_compare --baseline ../output/quality_baseline.json --current ../output/answer_quality.json
```

逐题检查正确性、忠实度、引用及拒答变化，防止A题改善抵消B题退化。
数据、策略、规则版本、评审配置不一致时拒绝比较；缺题、未评审及 calibration_fixture 报告不能作为正式基线。
真实 LLM 有随机性，应重复采样并人工检查回归，再决定是否更新基线，不应覆盖失败报告来制造通过。

## 本次实际验证范围

本地验证结果：新增评测模块37项测试通过；9组自检正反例全部符合预期；后端全量707项通过、19项真实模型测试因明确禁用API调用而跳过。数据库权限初始化已应用，跨租户与列权限20项集成测试以及宿主机/容器只读自检通过。语法检查及`git diff --check`通过。CI配置已加入自检，但尚未在GitHub上运行。

已验证离线评测器、正反例和原有问答契约。本次真实小样本尝试因沙箱网络限制未完成，3题均为调用错误，语义评分为null；沙箱外请求被自动审批拒绝，需明确授权向 SiliconFlow（api.siliconflow.cn）发送评测题目、检索片段，以及评审所需的参考答案和生成答案后才能继续。不得用历史检索分数或合成自检替代真实质量成绩。
本次入口针对经典 RAG。Agent 联合工具回答及 Text2SQL 的执行正确性仍使用各自测试，尚未纳入这个统一答案质量入口。
