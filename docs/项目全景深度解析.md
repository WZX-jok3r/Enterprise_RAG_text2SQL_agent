## 一、项目概述

**一句话**：一个前后端分离的多租户知识问答系统，以 RAG 检索文档、以只读 Text2SQL 处理全量统计，并由有界 Agent 工具循环协同回答；支持流式问答、异步入库和文档版本管理。

- **业务目标**：把散落的异构文档（PDF/DOCX/XLSX/MD/TXT）变成"有据可查、来源可溯、租户隔离"的问答服务；答不出来要明说（低相关过滤 + 拒答兜底），不许瞎编。
- **非目标（当前阶段）**：不做用户注册/登录体系（API Key 即租户）、不做文档在线编辑、不做多模型路由。
- **历史质量基线**：仓库冻结检索基线为 107 道题中 101 道参与来源判定、100 道命中（Recall@5=99.01%、MRR=0.9703）。测试数字以具体日期的验收记录为准，本文早期测试数量已过时。

## 二、总体架构与数据流

```
Browser ─► frontend(nginx :8080) ─ /api/v1 反代 ─► backend(FastAPI :8000)
                                                      │
              ┌───────────────────────────────────────┼───────────────────┐
              ▼                                       ▼                   ▼
        PostgreSQL :5432                        Qdrant :6333         Redis :6379
   documents/sessions/messages/          personal_rag_v2        session 热缓存 +
   ingest_tasks/tenants                  (dense+bm25+tenant ACL) ARQ 队列 rag_ingest
              ▲                                       ▲                   ▲
              └──────────── worker(ARQ 消费入库任务) ─┘───────────────────┘
                                    │
                                    ▼
                      SiliconFlow API（Embedding/LLM/Rerank）
```

四条主链路（详见第五节时序分解）：
1. **问答（读）**：API → 鉴权 → Retriever（Qdrant 混合召回→精排→低分过滤，强制叠加 tenant_id）→ 上下文组装 → LLM 生成 → 溯源返回。
2. **入库（写，异步）**：上传 → 落盘+登记+入队 → 秒回 202 → worker 解析/切分/向量化/索引 → 状态回写 → 前端轮询。
3. **会话**：PG 为持久化事实来源，Redis 用作热缓存；缓存未命中时会回源并重建缓存。Redis 连接异常不保证自动降级，具体行为应按服务调用路径核实。
4. **删除**：先清向量、再删物理文件、最后删登记行（失败保留现场可重试）。

## 三、模块逐一梳理（文件位置 / 重要方法 / 上下游）

### 3.1 `backend/app/core/` —— 全局地基

| 文件 | 重要内容 |
|---|---|
| `config.py` | `Settings(BaseSettings)` 单一配置源：模型/检索/过滤/分块/多租户/存储/会话/可观测全量字段 + 派生属性 `tenant_keys`（解析 `RAG_TENANT_KEYS=t1=key1;t2=key2` → `{key: tenant_id}` 反查表）、`auth_enabled`、`langfuse_enabled`、`postgres_url`(asyncpg 异步) 与 `sync_postgres_url`(psycopg，给 Alembic)、`knowledge_base_dir`（由 `__file__` 反推项目根，容器内自动变 `/knowledge_base` 与挂载点对齐）。env_file 双通道：根 `.env` → `backend/.env`，容器环境变量可覆盖（12-factor） |
| `security.py` | `resolve_principal(x_api_key, authorization)`：与框架无关的纯函数。X-API-Key 优先、Bearer 兜底；无 Key→401、Key 不认识→403、未配置租户表→**软关闭**返回匿名主体。`Principal(tenant_id, authenticated)` 是全链路租户过滤的唯一输入。升级 JWT/RBAC 只换这一个函数 |
| `exceptions.py` | 异常层级（Unauthorized/Forbidden/NotFound/…）+ `register_exception_handlers` 统一 JSON 错误体 |
| `logging.py` | `setup_logging(level)`：统一格式 `时间 | 级别 | 模块` |

上下游：被所有模块依赖；不依赖任何业务模块（零环）。

### 3.2 `backend/app/api/` —— 路由与依赖装配

- `deps.py`：`get_principal`（Header 解析→Principal）、`enforced_filter(client_filter, principal)`（**服务端强制注入 tenant_id 且剥除客户端传入的租户键**，多租户安全的关键闸口）、`resolve_top_k`、`get_pipeline/get_ingestion_service` 注入点。
- `v1/query.py`：`POST /query` → `run_in_threadpool(pipe.query, ...)`（同步桥接的样板）。
- `v1/chat.py`：`POST /chat`（非流式多轮：解析/自建 session → get_history → pipeline.query_with_history → append 双消息）；`POST /chat/stream`（SSE：`iterate_in_threadpool` 逐步驱动 `pipe.stream_chat`，事件 `meta/delta/done/error`）。
- `v1/sessions.py`：`POST /sessions` 新建、`DELETE /sessions/{id}` 删除（均带租户 ACL）。
- `v1/documents.py`：`POST /documents` 上传（202+task_id）、`GET /documents/{task_id}/status`、`GET /documents` 列表、`DELETE /documents/{id}`。
- `v1/health.py`：存活探针 + 检索/模型配置回显（**不探外部依赖**，秒回，避免容器互等死锁）。
- `router.py`：聚合挂 `/api/v1`。

### 3.3 `backend/app/rag/` —— RAG 编排（同步内核）

| 文件 | 重要方法 | 说明 |
|---|---|---|
| `pipeline.py` | `query(generate=)` / `query_with_history` / `stream_chat` | 只做编排：检索→组上下文→LLM→格式化 sources；无召回时拒答文案 `_REFUSE_NO_CONTEXT`；多轮无召回用"无相关参考资料"兜底不拒答。结果键与流式事件是**前后端/评测的契约**，改动即破坏兼容 |
| `retriever.py` | `search → (chunks, dropped)` | 薄封装 VectorStore，把 stats 里的 dropped 计数透传上去（前端"已隐藏 N 条"数据源） |
| `context_builder.py` | `build_context(chunks)` | 编号 + 来源标注 + 文本拼装 |
| `prompts/rag.py` | `SYSTEM_PROMPT` | "仅根据资料回答/不确定要说明"型约束模板，`{context}` 注入（提示词已从本包的 `prompts.py` 拆到 `app/prompts/`） |
| `source_formatter.py` | `format_sources(chunks, with_preview=)` | 问答带 preview、对话列表不带（省 token/带宽） |
- 全链路被 `observability.trace/span` 包裹（`rag_query/rag_chat/rag_chat_stream` + `retrieve` 子 span）。

### 3.4 `backend/app/vector/` —— 检索心脏

- `embedding.py`：`EmbeddingClient.embed`（批量、维度校验 1024）、`RerankClient.rerank(query, docs, top_n)`（SiliconFlow 交叉编码，返回 relevance_score+index）。
- `qdrant.py`（447 行，检索核心；全项目行数最多的是 `ingestion/loader.py`）：
  - `tokenize_for_bm25`：jieba 预分词 + 英数串保护（型号/SKU 不被切碎），**入库与查询对称调用**——BM25 质量的前提。
  - `VectorStore._ensure_collection`：named vectors：`dense`(1024) + `bm25`(sparse)；payload 索引；`_ensure_tenant_index` 给 tenant_id 建 keyword 索引。
  - `upsert_chunks`：批 50；`_generate_id = uuid5(text+metadata)` —— **幂等 upsert**，重灌不产生重复点。
  - `search(with_stats=True)`：`prefetch_k` 扩召 → `_hybrid_query`（dense+稀疏双路、**RRF 融合**）→ `_rerank_points`（rerank API 挂掉时**降级为原排序但必须按 top_k 截断**——历史踩坑点）→ `_filter_low_relevance` → 返回 (results, stats{dropped…})。
  - `_filter_low_relevance`：**按 score_kind 分支**——只有 rerank 绝对分走「绝对下限 SCORE_ABS_MIN + 强锚点相对断层 SCORE_REL_RATIO + 保底 SCORE_MIN_KEEP」组合策略；RRF/向量分只截断不设限（量纲安全）。
  - `delete_by_metadata(filter)`：按 `{"source": 文件名}` 精确清向量（重灌/删除共用）；`count`、`delete_collection`。
  - `get_vector_store()` 进程级单例（懒连接）。

### 3.5 `backend/app/ingestion/` —— 入库流水线（写路径）

- `loader.py`（1592 行，解析大全）：`compute_file_hash`(md5，用于增量判重)；PDF 表格**三级提取**：`extract_tables_with_pdfplumber` → PyMuPDF `get_tables` → `extract_tables_with_dict`+`detect_columns`（自研列边界检测兜底）→ 全失败 `_convert_pdf_with_marker`（marker 转 md，timeout 900s，未安装则降级为纯文本继续，**不中断**）；`preprocess_page` 清洗页眉页脚页码；`load_pdf/txt/md/docx/xlsx` + `load_file` 扩展名路由（白名单来自 settings）。
- `chunking/`：
  - `base.py`：`split_by_size`（滑窗+overlap）、`clean_page_number_markers`、`_is_protected_chunk`（表格/代码块为受保护块）、`merge_small_chunks`（**禁止跨类型合并**——历史踩坑：合并曾把表格和小文本粘一起破坏检索）。
  - `table.py`：`is_markdown_table` 识别、`table_rows_to_sentences`（**行级语义化**：humanize 列名+猜实体词+选关键列，把每行变成一句自然语言）、`split_markdown_table`+`prepend_header`（大表切块时每块都带表头）、`chunk_xlsx`（多 sheet/大表逐行化）。
  - `text.py`：`chunk_md`（按标题层级+表格感知）、`chunk_txt`、`chunk_docx`（段落与表格分别路由）。
- `indexer.py`：`ProcessedCache`（`processed_cache/cache.json`：rel_path→file_hash，**内容未变跳过**）；`process_file`（hash 判重→load→chunk→embed→upsert→record{status,chunk_count,file_hash…}）；`run_ingest(force/reset/patterns)` 批量入口 + `_normalize_tenants`（多租户定向入库，payload tenant_id 多值）；重灌前 `delete_by_metadata(source)` 先清旧点；CLI `main()`。

### 3.6 `backend/app/models + repositories + services + database` —— 持久化域

- 表（`migrations/versions/35fd0e1e9233_init_persistence.py` 建）：
  - `documents`：id/tenant_id/source(=文件名=Qdrant payload source)/file_hash/format/status(pending→ready)/chunk_count/meta_json；
  - `ingest_tasks`：task_id(uuid)/status(queued/running/done/failed)/progress/error/**document_id FK ON DELETE SET NULL**（删文档保任务审计）；
  - `sessions`：id(uuid4 hex=前端 session_id)/tenant_id/last_active_at；
  - `messages`：session_id FK CASCADE/role/content/**seq 会话内单调**（unique(session_id,seq)）；
  - `tenants`。
- `database.py`：`db` 单例——异步 engine(asyncpg, pool 20+10) + sessionmaker，lifespan init/dispose、healthcheck。
- `repositories/`：`document_repo.upsert/list_by_tenant/get_by_id/update_status/delete`、`session_repo.create/exists/get_recent_messages/next_seq/add_message/touch/delete`、`ingest_task_repo.create/get/update_status`。**约定：仓储只 flush 不 commit，事务边界在 service 层**。
- `services/ingestion_service.py`：`register_document`（uuid 前缀落盘防重名→建 Document(pending)+IngestTask(queued)→arq 入队，原子返回 task_id）；`delete_document`（**外部清理先行**：`_clear_source_vectors`(Qdrant) → `_remove_physical_file`(磁盘) → 都成功才删 DB 行；任一失败抛错保留登记行可重试。两个清理函数是模块级私有函数——专为**单测 monkeypatch**设计）；状态查询透传。
- `services/session_service.py`：`create/exists/get_history/append/delete`。`get_history`：exists ACL → Redis 命中则 touch 续期 → miss 则 PG 回源 + `reheat`；`append`：**先写 PG（真相）再写 Redis（缓存）**，租户不符静默跳过。

### 3.7 `backend/app/cache/redis.py`

`RedisClient` 惰性单例（decode_responses）；`SessionCache` 保存有界会话历史。缓存未命中时服务可从 PostgreSQL 读取并重建缓存；Redis 连接错误并非所有路径都自动转换成缓存未命中，不能据此承诺 Redis 故障只影响性能。

### 3.8 `backend/app/worker/` —— ARQ 异步入库

- `settings.py`：`RedisSettings.from_dsn(settings.redis_url)`（**坑：from_dsn 不是 from_url**）；`max_jobs=1`（同文件不并行重灌）、`job_timeout=600`；`on_startup` 建异步引擎并把 `sessionmaker/vector_store` 注入 ctx。
- `tasks/ingest.py`：`ingest_document(ctx, file_path, task_id, tenant_ids)` 状态机 `running(10) → asyncio.to_thread(process_file) → done(100)/failed(error)`；失败**重新抛出触发 ARQ 重试（max_tries=5）**；`ctx.get("process_file")` 允许测试注入 fake——**hermetic 单测的关键设计**。
- `pool.py`：API 侧 `create_arq_pool/close_arq_pool`（lifespan 管理，入队用）。

### 3.9 `backend/app/llm/ + observability/`

- `provider.py`：`LLMClient.complete(messages)→(text, usage)`、`stream(messages)→Iterator[str]`；OpenAI 兼容协议调 SiliconFlow；temperature/max_tokens 从 settings；异常原样上抛由 pipeline 决定文案。
- `observability/langfuse.py`：`trace()/span()` 上下文管理器封装；`langfuse_enabled=False` 时**全链路 no-op 零开销**（软依赖设计）；记录 input/output/metadata（sources、retrieved/hidden count）。

### 3.10 `backend/migrations、eval、tests`

- Alembic：异步应用/同步迁移双 URL；`alembic.ini` 注释保持纯 ASCII（**Windows locale=GBK 读 ini，中文注释会崩**）。

## 四、端到端调用链（时序）

### 4.1 上传入库
`POST /documents`（multipart）→ `documents.py upload` → `IngestionService.register_document`：`knowledge_base_dir` 落盘（`uuid8_原名`）→ `DocumentRepository.upsert`(pending) + `IngestTaskRepository.create`(queued) → `arq pool.enqueue_job("ingest_document", path, task_id, tenant_ids)` → **202 返回 task_id**。
worker 侧：`ingest_document` 置 running(10) → `to_thread(process_file)`：hash 判重→`load_file`→`chunk_document`→`EmbeddingClient.embed`→`upsert_chunks`→record → Document upsert(ready, chunk_count) → task done(100)。异常→failed(error)+raise→ARQ 重试。
前端轮询：`GET /documents/{task_id}/status` → `ingest_task_repo.get`（ACL 按租户）。

### 4.2 单轮问答
`POST /query` → `get_principal` → `enforced_filter` 注入 tenant_id → `run_in_threadpool(pipe.query)` → `Retriever.search` → `VectorStore.search`：embed_query → prefetch 混合召回(dense+bm25 RRF) → rerank API 精排（失败降级截断） → `_filter_low_relevance`(score_kind=rerank) → `(chunks, dropped)` → `build_context` → `LLMClient.complete` → `format_sources(preview)` → 响应 + Langfuse trace。

### 4.3 流式多轮
`POST /chat/stream` → session 解析（不存在/非本租户→自动新建并回传 session_id）→ `get_history`（Redis→miss PG reheat）→ `iterate_in_threadpool(pipe.stream_chat)`：检索完先 yield `meta{sources,retrieved,hidden}` → `LLMClient.stream` 逐 token `delta` → `done{answer}`；结束后 `append` user+assistant 双消息（PG 先、Redis 后）。nginx `proxy_buffering off` 保证逐帧透传。

### 4.4 删除文档
`DELETE /documents/{id}` → `get_by_id(id, tenant)`（**跨租户=404**）→ `_clear_source_vectors(source)` → `_remove_physical_file(source)` → 删 Document 行（ingest_tasks 由 SET NULL 保审计）→ 返回 `{vectors_cleared, file_removed}`。

## 五、亮点盘点（决策 + 为什么）

1. **两级混合检索**：dense(bge-m3) + BM25 稀疏双路 RRF 融合，再交叉编码(bge-reranker-v2-m3)精排。语义与关键词互补，型号/编号类查询不靠运气。
2. **量纲安全的低相关过滤**：识别出"RRF 分/向量分/rerank 分量纲不可互通"这一普遍误区，仅对 rerank 绝对分建阈值体系（绝对下限+相对断层+保底 N 条），既"宁缺毋滥"又不整页误杀；过滤计数全链路透传到前端徽标——**可解释性做进了 UI**。
3. **单 collection 多租户 ACL**：服务端检索入口强制应用租户过滤；开发配置允许关闭鉴权，但该模式不提供租户隔离。更换身份提供方时需重新核对所有授权入口，不能假设只改一个函数。
4. **同步内核 + 异步外壳的桥接工艺**：`run_in_threadpool`（问答）、`iterate_in_threadpool`（SSE）、`asyncio.to_thread`（worker 重活）三种桥接各司其职，事件循环永不阻塞，也没把同步代码硬改成 async 重写一遍（迁移风险控制）。
5. **幂等与自愈的入库设计**：uuid5(text+meta) 点 ID → 重复 upsert 天然幂等；重灌先按 source 清旧点 → 无新旧混叠；worker 失败 re-raise 交给 ARQ 重试；ProcessedCache hash 判重 → 批量重跑秒过。
6. **表格检索专项**：行级语义化（每行→一句自然语言，带表头与实体语境）、大表切块逐块补表头、受保护块禁止跨类型合并、PDF 表格三级提取 + marker 兜底降级——结构化数据不再是 RAG 黑洞。
7. **PG 持久化 + Redis 热缓存**：会话数据有 PostgreSQL 持久化路径，缓存未命中时可重建；Redis 连接故障可能让请求失败，因此不能承诺 Redis 全部故障仅损失性能。
8. **删除的一致性次序**：外部资源（向量/文件）清理成功才删登记行，半途失败保留记录可重试；FK `SET NULL` 保留任务审计。
9. **可观测是软依赖**：Langfuse 未配置时全 no-op，配置后 trace/span 自动点亮，代码零改动。
10. **验证分层**：后端逻辑与集成测试、离线评测、Compose 运行态验收各自覆盖不同风险。具体数量与结果均为带日期的历史记录，见 README 的验证章节和专项报告。
11. **交付工程化**：compose 一次性 migrate 服务用 `service_completed_successfully` 编排 schema 先于应用；单镜像双角色（API/worker）；Dockerfile 层缓存（改前端源码重建仅秒级）；pydantic-settings 单一配置源与旧 .env 100% 兼容。

## 六、不足与技术债（现状 → 影响 → 改进）

### 安全
1. **API Key 静态配置**：租户 Key 由配置提供；轮换、吊销和用户级身份管理能力有限。→ 生产应结合密钥管理与身份提供方设计密钥生命周期。
2. **租户内权限粒度有限**：已有角色与 SQL 列级权限控制，但没有完整的同租户用户/部门文档 ACL。→ 需要把身份和授权规则贯穿文档、向量、列表、版本与历史数据路径。
3. **浏览器运行时保存 API Key**：当前前端从 localStorage 读取 Key，不将共享凭据编译进公开构建产物；同源脚本仍可读取 localStorage，XSS 风险和正式用户身份方案仍需评估。
4. **无限流/配额**：`/query` 直通 LLM，恶意刷可烧穿预算。→ nginx limit_req 起步，进阶按租户令牌桶 + token 用量配额。
5. **无 HTTPS/CORS 仍开发态白名单**。

### 规模与性能
6. **worker 单并发（max_jobs=1）**：吞吐上限低，大文件会堵队尾。→ 分队列（大/小文件）、按租户限流并发、多 worker 副本 + 幂等保护已具备可直接扩。
7. **rerank 同步外呼无缓存**：每次查询都打 rerank API（延迟+费用+故障面）。→ 查询级 LRU/短 TTL 缓存、批量归并。
8. **Qdrant 单节点嵌入部署**：无副本无分片规划；BM25 稀疏索引中文依赖 jieba 分词质量，无同义词/字段加权。
9. **会话并发竞态**：同 session 双标签页并行发消息，`next_seq` 读-增-写存在竞态，可能撞 unique(session_id,seq) 报错。→ seq 改 DB 序列或行锁。

### 质量与运维
10. **评测与门禁仍需完善**：仓库已有答案质量指标、judge、比较工具和起始标注集，但真实答案评审规模有限，评测没有形成完整 CI 门禁；107 题检索基线也不代表业务覆盖充分。
11. **CI 覆盖有限**：仓库已有 GitHub Actions 运维工作流，但它不等于完整的测试、前端构建与评测质量门禁；应以 `.github/workflows/` 当前配置为准。
12. **恢复能力有边界**：仓库已有备份、对账与恢复演练工具及专项记录；报告中记载的 Qdrant 物理快照问题和未覆盖的灾备环节仍需单独处理，不能概括为“没有备份/恢复演练”。
13. **对账自动化有边界**：已有对账脚本和运维工作流，但是否在目标主机持续调度、是否覆盖版本化存储路径及告警需要单独验收。
14. **observability 部署有边界**：仓库已有 `/metrics`、trace ID、Langfuse 与性能记录工具；这不等于生产环境已配置采集、长期存储、worker 全链路关联和告警。
15. **前端功能面**：无分页/搜索/批量删除/下载原文件；单会话模型（无历史会话列表切换）；错误提示较原始。

## 七、真实踩坑清单（全部在本项目发生过）

| # | 坑 | 处置 |
|---|---|---|
| 1 | rerank 降级分支忘了按 top_k 截断 → 候选扩量后返回超量结果 | 降级路径统一 `[:top_k]`，单测钉死 |
| 2 | merge_small_chunks 把受保护表格块与普通文本合并 → 检索质量回退 | `_is_protected_chunk` 禁止跨类型合并 |
| 3 | Qdrant payload `source` 与删除键不一致 → 向量残留 | 统一"文件名=source=删除键"约定，重灌/删除共用 delete_by_metadata |
| 4 | nginx 上游 DNS 缓存：单独重建 backend 换 IP → :8080 全 502 | `docker compose restart frontend`；写进 README 常见坑 |
| 5 | nginx alpine 健康探针 `localhost` IPv6 解析失败 | 探针改 `127.0.0.1` |
| 6 | compose SSE 被缓冲，流式变整块 | 该 location `proxy_buffering off` |
| 7 | alembic.ini 中文注释在 Windows 按 GBK 读崩 | ini 注释保持纯 ASCII |
| 8 | `arq.connections.RedisSettings.from_url` 不存在 | 用 `from_dsn` |
| 9 | Langfuse v4 移除 `start_as_current_span` 类 API | 封装 trace/span 上下文管理器适配层 |
| 10 | PyCharm 往 venv 塞 pytest 与 `uv run` 隐式 sync 互搏 → 每次启动卸 N 装 N | dev 依赖改 PEP 735 `[dependency-groups]`（已修，见 bbd80e6） |
| 11 | uv 缓存(C 盘)与 venv(D 盘)跨盘 hardlink 失败 | 性能警告可 `UV_LINK_MODE=copy` 消除 |
| 12 | `.app-header` 的 backdrop-filter 创建层叠上下文，header 内下拉被正文卡片盖住 | Teleport 到 body 的居中模态 |
| 13 | compose `${VAR:-default}` 的 `:-` 被拆成 `:` → 插值语法非法 | 恢复 `:-`，`docker compose config --quiet` 校验 |
| 14 | PowerShell 吞引号/管道/括号，curl 内联中文 JSON 转义坏 | 一切复杂命令写 .ps1；请求体走 UTF-8 文件 `--data-binary @file`；`curl.exe` 防别名 |
| 15 | SSE 中文按字节 flush 乱码 | TextDecoder(stream) 解码 + 帧缓冲 |
| 16 | `docker compose down -v` 会清空 PG/Redis volume | 演示复位只用 `down`；qdrant_storage 是 bind mount 同样别 -v |
| 17 | tsconfig composite 工程配 `noEmit` 报错 | 关闭 noEmit，由 vue-tsc 把关 |
| 18 | 孤儿登记行（物理文件已删但 DB 有记录） | 用 DELETE /documents/{id} 清理（file_removed:false 也放行删登记） |
