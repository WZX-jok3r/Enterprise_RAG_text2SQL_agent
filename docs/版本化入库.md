# 版本化入库

API上传的文档现在按“租户 + 原始文件名（basename，区分大小写）”形成版本链。存储副本使用UUID文件名，保存在`knowledge_base/.versions/`；不覆盖历史文件，不参与旧CLI的目录扫描。

## 行为与边界

- 同名、不同内容的上传生成递增版本；最新版本相同内容且处于pending/ready时复用版本及任务。重新上传历史内容会生成新版本，不自动回滚。
- 新版本先写入带`document_version_id`的独立向量，完整成功后在PostgreSQL事务内切换当前版本。解析为空、部分写入失败、文件哈希不一致均不能发布；旧当前版本继续可用。
- 同一文档链使用事务级advisory lock串行处理入库、发布、回滚和删除；并发重复任务不会重复清理已发布向量。同名上传可能等待该文档正在进行的入库，其他文档链独立处理。
- 查询在dense、BM25预取与融合结果中同时施加“当前版本 + 租户”的过滤。数据库不可用时停止检索，不降级返回历史版本。每次检索采用一次数据库当前版本快照，切换不会改写已经开始的回答或聊天历史。
- ready表示入库完整，is_current表示用于默认问答，两者不能混用。较旧版本晚完成时不会替换已就绪的新版本。
- 回滚只切换当前指针，不重新调用Embedding。存在pending/failed版本时返回409；先等待任务完成或删除未完成版本，避免后台重试覆盖回滚。
- 删除只影响指定版本：先标记deleted并撤销当前指针，再按版本ID清理向量与文件。失败可重试，保留删除记录及版本号。删除当前版本不会自动启用历史版本，需要显式选择其他ready版本。
- 版本历史、回滚和删除严格校验租户，包括匿名身份；跨租户返回404。

迁移保留现有普通文档及无版本标识的历史向量，不推断旧UUID文件对应的业务版本。它们仍走原有检索逻辑，不属于新的版本链。正式迁移存量资料时，应先确认原始文件名与归属，重新通过API上传并核验，然后清理对应旧登记及旧向量，避免旧资料与新版本并存。

本次版本化范围为API上传后的RAG索引。旧CLI仍是原来的增量入库方式；版本化表格暂不自动同步Text2SQL，任务记录的`analytics_sync.reason`会说明原因，前端上传区也提示这一点。SQL表的版本发布需要独立实现，不会把历史表格静默覆盖为“当前数据”。

## 部署与使用

先暂停旧worker，完成迁移后同时更新API和worker代码，再启动服务，避免旧worker忽略新增的版本任务参数。在backend目录执行：

```powershell
..\.venv\Scripts\python.exe -m alembic upgrade head
```

本地已应用迁移至`a271c48319b6`。迁移只增加字段与约束，现有记录不变；一旦已有版本历史，禁止直接降级删除版本字段，需先导出并制定迁移方案。`create_all`不能代替已有数据库的迁移。

继续使用`POST /api/v1/documents`上传，文件名决定版本链。任务状态和文档列表新增`document_key`、`version`、`original_filename`及`is_current`。答案来源新增可选的`document_version_id`与`document_version`，用于确认引用版本。前端文档抽屉展示每个版本及当前标识，历史ready版本可点击“设为当前”。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/documents/{document_id}/versions` | 查看所属文档链，按版本倒序，包括删除记录 |
| `POST /api/v1/documents/{document_id}/activate` | 将指定ready版本设为当前，含回滚 |
| `DELETE /api/v1/documents/{document_id}` | 删除指定版本，可重试清理 |

## 验证

每小步通过对应验证后再继续：数据库模型与迁移、版本入库状态机、检索与回滚、前端与联合验证。

```powershell
..\.venv\Scripts\python.exe -m pytest tests/test_document_versions.py tests/test_version_visibility.py tests/test_versioned_indexing.py -q
```

覆盖真实PostgreSQL并发分配/唯一约束、幂等上传、入队失败、失败重试、文件变动拦截、并发重复任务、删除失败重试、回滚与跨租户API404；Qdrant内存引擎验证过滤语义，独立本地Qdrant测试集合验证PostgreSQL发布前后与回滚后的检索结果。联合测试使用合成文本与固定向量，不向外部模型发送知识库数据，不能代替真实Embedding或答案质量评测。

本次结果：新增版本化测试22项全部通过；后端全量729项通过，19项真实模型测试明确禁用外部调用后跳过；前端`npm run build`、语法检查及`git diff --check`通过。本地PostgreSQL迁移到head，本地生产集合已确认建立`document_version_id`的keyword索引。测试集合独立创建并清理，没有重新入库或清空现有知识库。

规模限制：当前检索每次从PostgreSQL读取当前版本ID集合，适合本项目规模。大规模文档库需要进一步按租户限制查询、优化版本路由或引入索引快照；不能直接加过期缓存，否则回滚和删除会延迟生效。
